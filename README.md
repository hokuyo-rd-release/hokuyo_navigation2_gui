# hokuyo_navigation2_gui

`hokuyo_navigation2_gui`は、ROS 2ベースのナビゲーションおよびマッピングシステムを直感的に操作するためのWebベースのGUIです。

Flaskサーバーを介して提供され、マッピング、ナビゲーションの実行、および関連するファイル（マップ、ウェイポイントなど）の管理をブラウザから簡単に行うことができます。

## 主な機能

### 1. データ取得
- ROS Bag を取得するためにセンサやロボットのノードを起動します。

### 2. マッピング

- **3D SLAMと2Dウェイポイントファイル出力の同時実行**: ROS Bagファイルを使用して、以下のSLAMアルゴリズムを実行します。SLAM実行時にウェイポイントファイル`.json`が作成されます。
  - `p2o` ([hokuyo_slam](https://github.com/hokuyo-rd/hokuyo_slam_ros2.git)を用いた3D点群マップ)
  - `lio_raw` (LiDAR Inertial Odometry の軌跡に基づく3D点群マップ)

![画像](Image/expo2025.png)

- **ROS Bag の内容表示**: ROS Bag を選択すると、記録されているトピックの一覧を
  ブラウザ上に表示します。トピック名・メッセージ型（日本語の説明つき）・メッセージ数・
  おおよその周波数・座標系（`frame_id`）に加えて、記録時間やファイルサイズも確認できます。
  メッセージが1件も入っていないトピックは強調表示されます。

- **設定チェック**: パラメータ設定ファイル（CSV）を選ぶと、その内容と ROS Bag の中身を
  突き合わせて、実行前に問題を知らせます。
  - コンフィグに書かれたトピックが ROS Bag に無い／中身が空／型が違う場合に、
    そのROS Bagに実際に入っている候補を提示します。
  - `orig_frame` / `target_frame` が ROS Bag のオドメトリの座標系と一致しない場合に警告します。
    （一致しないと、エラーが出ないまま中身が空の地図が作られてしまいます）
  - 設定ファイルの行の並び順が崩れている場合に警告します。
    マッピングのスクリプトは CSV を行番号で読むため、並べ替えると値がずれてしまいます。

- **設定ファイルのその場編集**: マッピングの実行画面で、パラメータ設定ファイル（CSV）を
  そのまま書き換えて保存できます。
  - トピック名の項目は、**選択中の ROS Bag に実際に記録されているトピック**が
    プルダウンの候補になります。メッセージ型が合っていてデータが入っているものには
    ★ が付き、先頭に表示されます。
  - 座標系（`orig_frame` / `target_frame`）は、ROS Bag に出てくる座標系が候補になり、
    オドメトリと一致するものに ★ が付きます。
  - 候補にない値を使いたい場合は「（直接入力）」を選ぶと文字入力に切り替わります。
  - 選択肢は色分けされます。**緑**は型が合っている／座標系が一致している候補、
    **赤**は選択中の ROS Bag に存在しない値です。
  - 別のファイル名を入力すれば、元のファイルを残したまま新しい設定として保存できます。
  - 保存すると設定チェックが自動でやり直されます。
  - 行の並び順とデフォルト値の列はそのまま保持されます（実行スクリプトが CSV を
    行番号で読むため、並べ替えると値がずれてしまいます）。

- **実行ログの表示**: マッピングや変換の実行ログをブラウザ上に表示します。
  ログの内容から失敗の原因を判別し、「点群トピック名が違う可能性がある」「ディスクの
  空き容量が足りない」といった日本語の説明と対処方法を表示します。
  処理が異常終了した場合は、完了を待たずにその場で失敗を知らせます。

- **データ処理**:
  - **PCDからPGMへの変換**: 3D点群マップ（`.pcd`）を2D占有格子マップ（`.pgm`と`.yaml`）に変換します。オプションとして、変換の際に`.json` 形式のウェイポイントファイルを指定すると、.pgm`マップ状に、指定したウェイポイントに沿って通行可能領域を生成します

![画像](Image/pcd2pgm.png)
![画像](Image/pgm_waypoint.png)

### 3. ナビゲーション
- **単一マップ走行**: 指定したマップとウェイポイントファイルを使用して自律走行を開始します。自律走行は実行時に、GNSSベースか、LiDARベースの自律走行のどちらか1つを選択できます。
- **マルチマップ走行**: 複数のマップとウェイポイントを順番に走行するシナリオをCSVファイルで定義し、実行します。
- オペレータに安全意識を向けることを目的として、自律走行の開始条件としてチェック欄への入力が必須とする仕様になっています。(文言は一例なので、適宜変更してください。)

### 4. ファイル管理
- **ブラウザベースのファイル管理**:
  - マップ (`.pcd`, `.yaml`, `.pgm`)
  - ウェイポイント (`.json`)
  - 設定ファイル (`.csv`)
- **ファイル/フォルダ操作**: ディレクトリの作成、ファイルやディレクトリの削除、名前の変更が可能です。

### 5. 編集ツール


- **Map Viewer (3D)**:
  - PCDマップとPGMマップを3D空間で視覚化します。
  - **ウェイポイント編集**:
    - **追加**: マップ上をクリックして新しいウェイポイントを追加（先頭、末尾、選択中の後）。
    - **移動**: クリックで選択してから、ドラッグ＆ドロップで位置を調整。
      選択していないウェイポイントはドラッグしても動きません。
    - **回転**: ギズモ(半円状のUI)を使用してウェイポイントの向き（Yaw角）を編集。
    - **属性編集**: ウェイポイントの種別（`normal`, `slow`, `stop`）や速度などの属性を編集。
    - **保存**: 編集したウェイポイントをサーバーに保存。
  - **初期位置の指定 (自己位置推定)**:
    - `simple_fastlio_localization` の初期位置を、**ウェイポイントと同じ操作**で編集できます。
      - **選択**: マゼンタ色の矢印マーカーをクリックすると選択され、回転ギズモが表示されます。
        地図上での見え方を変えないよう、選択してもマーカーの色は変わりません（選択中かどうかはギズモの有無で分かります）。
        ウェイポイントを選択中でも、マーカーをクリックすればそのまま切り替わります。
      - **移動**: 選択後、そのままドラッグして位置を動かせます。
        選択していないマーカーはドラッグしても動きません（誤操作で初期位置がずれるのを防ぐため）。
      - **回転**: ギズモ（青い輪）をドラッグして向き（Yaw角）を変更します。
        ギズモの上で押した場合は移動より回転が優先されるため、マーカーが小さく表示される
        （カメラが遠い）状態でも向きを変えられます。
      - **数値入力**: X / Y / Yaw の入力欄でも指定でき、「マップ上でクリックして指定」で離れた場所へ一度に移動できます。
    - 移動・回転の結果はその場で入力欄に反映されます。
    - 保存すると `data/<マップ名>/init_pose.txt` に `x,y,z,qx,qy,qz,qw` 形式で書き込まれ、
      自律走行の起動時 (`nav_common.sh` の `load_initial_poses`) に読み込まれます。
    - マップをロードすると、保存済みの初期位置が自動で読み込まれます。
    - **地図の原点を初期位置に合わせる**: 「保存するとき、地図の原点を初期位置に合わせる」がオン (既定) のまま「初期位置を保存」を押すと、
      初期位置 (x, y) が新しい原点 (0, 0) になるよう、地図一式の座標を (-x, -y) だけ平行移動します (向きと高さは変えません)。
      書き換えるファイルを一覧で確認してから実行します。
      | ファイル | 書き換える内容 |
      |---|---|
      | `map/<名前>.yaml` | `origin` (PGM の画素はそのまま) |
      | `map/<名前>.pcd` | 点の x, y (x y 以外の項目や ascii / binary の形式はそのまま) |
      | `waypoints/<名前>.json` | 各ウェイポイントの x, y (4 要素目の緯度経度高度は場所が変わらないのでそのまま) |
      | `data/<名前>/init_lat_lon_alt.txt` | 新しい原点の緯度・経度 (`fix2xyz` と同じ UTM で計算。高度はそのまま)。GNSS を使わずに作った地図の既定値のときは変えない |
      | `data/<名前>/init_pose.txt` | (0, 0, z) と初期位置の向き |
      | `data/<名前>/source_points.pcd`, `map_params.json` など | 地図のパラメータ調整の元の点群・範囲・原点 |
      - 表示中の点群・2D地図・ウェイポイント・カメラ・Google 背景の原点も同じだけずらすので、見た目は変わりません (原点の矢印とグリッドだけが初期位置へ移ります)。
        2D マップの保存していない編集はそのまま残ります。
      - 表示中のウェイポイントが別の名前のファイルのときは、画面上だけずらすので「ウェイポイントを保存」で保存してください。
        別の名前の地図のファイルや、`data/<名前>/` のマッピングの途中結果 (`poses.txt` など) は書き換えません。
      - すべてのファイルを書き終えてから置き換えるので、途中で失敗したときはどのファイルも変わりません。
        大きな ascii の PCD は書き換えに時間がかかります。
      - 新しい原点の緯度経度は、`fix2xyz_node` と同じ定義 (原点の UTM + 初期位置の x, y) で計算します。
        実際の `fix2xyz_node` / `xyz2fix_node` で、ずらす前後の GNSS 座標とウェイポイントの位置が 0.01 mm 未満で一致することを確認しています。
      - `fix2xyz` は点ごとに経度から UTM ゾーンを決めるため、初期位置が UTM ゾーンの境目 (`fix2xyz` の式では経度 133°, 139°, 145° など) の
        向こう側にあって新しい原点のゾーンが変わる場合は、GNSS の位置が地図とずれるので、原点を合わせずに止めます。
      - オフにすると、これまでどおり初期位置だけを保存します。
  - **2Dマップ (PGM) の編集**:
    - PGM/YAML を読み込むと「2Dマップ (PGM) 編集」パネルが表示されます。
    - **ブラシ**: 「通行可 (白) / 障害物 (黒) / 未知 (グレー)」を選び、半径[m]を指定してマップ上をドラッグして塗ります。
      塗りに使われるのは**2Dマップの上で押したときの左ドラッグだけ**です。ウェイポイントや初期位置マーカー、
      ギズモの上で押した場合はそちらの選択・移動・回転が優先され、マップの無いところで押した場合はカメラ回転になります。
      そのため、ブラシを選んだままでも他の操作をそのまま続けられます。
      ブラシは「なし」を選ぶか **Esc** キーで解除できます（ウェイポイント追加モードや初期位置の指定モードに入ると自動で解除されます）。
    - **ウェイポイント追従**: 「ウェイポイント移動に追従して通行可にする」を有効にすると、
      ウェイポイントをドラッグまたは座標入力で動かすたびに、指定した**マージン[m]**の幅で
      そのウェイポイントの周囲と前後の区間がリアルタイムに通行可領域へ描き換わります。
      （`pcd2pgm_converter.py` の `waypoint_tolerance` と同じ考え方の処理を、その場で行います）
      ウェイポイントを**置き直すと、前の場所で塗った分は置く前の状態に戻ります**（塗り跡が残りません）。
      他のウェイポイントの塗りつぶしと重なっている部分は、そちらが残っている限り通行可のままです。
      ウェイポイントを削除したり、途中に挿入したりしたときも、無くなった区間の塗りつぶしは元に戻ります。
      なお、追従で塗られた場所をブラシで塗り直した画素は手動編集として扱われ、元には戻りません。
    - **範囲の表示**: 「通行可にする範囲を表示」（既定でオン）で、通行可になる範囲を地図の上に水色で重ねて表示します。
      各ウェイポイントを中心とする円と、その間を結ぶ帯が、いま指定しているマージンの幅で描かれます。
      マージンを変えると即座に反映されるので、塗る前に範囲を確かめられます。
    - **保存**: 元のマップ名で上書き、または別名を入力して `.pgm` と `.yaml` を新規保存できます
      （別名保存時は元の YAML の解像度・原点を引き継ぎます）。
    - 「編集を破棄」で読み込み直後の状態に戻せます。未保存のまま画面を閉じようとすると警告します。
  - **Google 背景 (航空写真 / 3D)**:
    - 「Google 背景」パネルの「表示」で、点群・PGM・ウェイポイントの下に Google のデータを重ねます。
      - **2D 衛星写真**: Map Tiles API の衛星写真を地面に並べます。**並べる範囲と解像度は、カメラの拡大縮小・移動に合わせて自動で変わります。**
        カメラが止まると、画面中心 (注視点) のまわりは画面の細かさに合う写真 (最大ズーム 20)、その外側の見えている範囲は粗い写真で埋めます。
        ズームアウトは最大 5km まで引けるので、広い範囲を見渡せます。「透過度」で透かせます。
        一度読んだ写真はページを開いている間メモリに残すので、拡大縮小を戻したときは読み直しません
        (1 視点あたり最大 128 枚。カメラを動かすたびに新しい範囲の写真を読み込みます)。
      - **3D (Google Earth 相当)**: Photorealistic 3D Tiles の建物・地形を重ねます。
        既定では「点群・2D地図・ウェイポイントを 3D Tiles の手前に表示する」がオンで、3D Tiles を背景として描くため、
        建物や木、地面の起伏に PGM やウェイポイントが隠れず、上から見たまま選択・ドラッグ・ブラシ編集ができます
        (点群・PGM・ウェイポイントどうしの前後関係はこれまでどおり)。オフにすると、実際の高さどおりに隠れて見えます。
        PGM が写真を覆って見にくいときは「PGM透過度」で透かしてください。
    - **3D 地図 (PCD) が無くても表示できます。** PGM やウェイポイントだけをロードした場合も、その地図の原点で重ねます。
    - **場所を検索**: 「場所を検索」に住所・地名・緯度経度を入れて Enter (か「検索して移動」) を押すと、その場所に赤いピンを立てて表示します。
      - 緯度経度は `35.6986, 139.8176`、`139.8176, 35.6986` (経度が先)、度分秒 (`35°41'55"N 139°49'03"E`、`北緯35度41分55秒 東経139度49分3秒`)、
        Google マップの URL (`.../@35.69,139.81,17z` など) のどれでも読めます。この場合は Google に問い合わせません。
      - 住所・地名は GUI サーバーから Google に問い合わせます (Geocoding API。見つからないか一部一致だけのときは Places API (New) でも探します)。
        候補が複数あれば一覧に出るので、選ぶとその場所へ移動します。
      - いまの原点 (ロード中の地図など) から 10 km 以内なら、原点はそのままでカメラをその場所へ動かします。
        遠い場所や、原点が決まっていないときは、その場所を原点にします (地図をロード中なら確認します。ロード中の地図とは重ならなくなります)。
        3D 表示で離れた場所へ動いたときは、地面の高さを合わせ直します。
    - **デバイスの現在地**: マップを指定せずに Map Viewer を開くと、ブラウザの位置情報でデバイス (PC・タブレット) の
      現在地を取得して原点にし、2D 衛星写真を自動で表示します。ブラウザが位置情報の許可を求めてきたら許可してください。
      「デバイスの現在地を原点にする」ボタンでいつでも取り直せます (地図をロード中に押すと、原点だけ現在地に差し替わります)。
      - ブラウザの制限で、位置情報は **GUI を HTTPS か localhost で開いたときだけ**使えます。
        別の端末から `http://<IP>:5050` で開いている場合は、[HTTPS で起動する](#4-https-で起動する-デバイスの現在地を使う場合) を参照してください。
      - 精度は端末によります。GPS の無い PC は Wi-Fi などから推定するため、数十 m 以上ずれることがあります (精度は原点の表示に出ます)。
      - 位置情報の高度は取れないことが多いので、3D は毎回、読み込み後に高さを自動で合わせ直します。
      - 取得できなかった場合は、手入力で保存した原点があればそれを使います。
    - 何もロードしていない場合は、ほかに「原点を手入力する」で緯度経度を入力するか、
      「既存マップの原点を入力欄に入れる」で同じ現場の地図 (GNSS で作ったもの) の原点を選んで「この原点を使う」を押します。
      マップ無しで入力した原点はブラウザに保存され、次に Map Viewer を開いたときも使われます。
    - 位置合わせには、マップの原点 `data/<マップ名>/init_lat_lon_alt.txt` を使います。
      地図座標は `fix2xyz` と同じく「UTM (ゾーンの決め方も fix2xyz と同じ) で原点からの差」なので、
      子午線収差 (東京付近で約 0.7°) も含めて重なります。
    - **高さ補正**: 原点の高度は Google のデータの高さの基準 (WGS84 楕円体高) と合わないことが多く、
      3D Tiles が数十 m 浮いたり沈んだりします。3D を初めて表示したときは、読み込み後に画面中心の地面へ自動で合わせます。
      合わせるときは、読み込み始めの粗いタイル (実際の地面から数 km ずれている) は使わず、画面中心の真下の細かいタイルを
      読み込んでから測ります (カメラが地表の下に入っていても読み込みます)。
      屋根などに合ってしまった場合は、平らな地面を画面中心にして「画面中心の地面に高さを合わせる」を押してください。
      3D では、地面にぴったり合わせると写真から作った地面の凹凸に PGM やウェイポイントが埋もれるので、
      画面中心のまわりの地図の真下 (PGM の通行可の所・ウェイポイント) の地面を測り、その凹凸の上端が
      点群の地面・PGM・ウェイポイントより 5 cm 下になるように合わせます (自動で合わせたときも同じ)。
      木・屋根・高架など地面より 1 m 以上高い物は高さどおりに手前に来るので、その下のウェイポイントは隠れます
      (隠れる個数を表示します)。そのときは「点群・2D地図・ウェイポイントを 3D Tiles の手前に表示する」を使ってください。
      点群をロードしていないときは、地図の z=0 (PGM・ウェイポイントの高さ) を地面として合わせます。
      補正値はマップごとにブラウザへ保存されます。
    - **原点の手入力**: GNSS を使わずに作った地図は原点が既定値 (`35.0,135.0,40.0`) のため重ねられません。
      「原点を手入力する」で緯度・経度・高度・方位補正を入力すると重ねられます。
      入力値はブラウザにだけ保存され、自律走行で使う `init_lat_lon_alt.txt` は変わりません。
    - 表示中は、利用規約に従い画面下に Google の表記と出典を表示します。
  - **範囲から地図を作る (Google 3D)**:
    - Google 背景を表示すると「範囲から地図を作る」パネルが出ます。「範囲をドラッグで選択」を押して地図の上を左ドラッグし、
      マップ名を入れて「PCD・PGM を作成して保存」を押すと、次のファイルを作ります (1 辺 5〜400 m)。
      | ファイル | 内容 |
      |---|---|
      | `map/<名前>.pcd` | 選んだ範囲の Google 3D Tiles のメッシュ表面に、指定した間隔で点を置いたカラー点群 (binary PCD、`FIELDS x y z rgb`)。色はメッシュの写真 (テクスチャ) から取る |
      | `map/<名前>.pgm`, `.yaml` | 点群から作った 2D 地図。場所ごとの地面からの高さが指定の範囲 (既定 0.5〜2.0 m) にある所を障害物にする |
      | `data/<名前>/init_lat_lon_alt.txt` | 範囲の中心の緯度・経度と、そこの地面の高度 (WGS84 楕円体高) |
      | `data/<名前>/init_pose.txt` | 初期位置。範囲の中心 (地図の原点) に向き 0° で置く |
      | `data/<名前>/map_params.json` | 作ったときの設定 (点の間隔・範囲・PGM の設定)。後から「地図のパラメータ調整」で作り直すときに使う |
    - 点群と PGM は、範囲の中心を原点に `fix2xyz` と同じ UTM の座標 (X=グリッド東, Y=グリッド北) で作るので、
      GNSS モードの自律走行でそのまま重なります。自律走行の launch は `src` の `map/` を読むため、ビルドは不要です。
    - 作り終わるとその地図に切り替わります。「初期位置」パネルで初期位置を、ウェイポイント編集でウェイポイントを置いて保存してください。
    - 画面の表示とは別に、範囲の真上から細かいタイルまで読み込むので、数十秒〜数分かかり、3D Tiles の読み込み (課金対象) も発生します
      (約 36 m × 32 m の範囲で 3D Tiles 約 160 回、約 1 分)。「作成を中止」で止められます。
    - 高度は Google のメッシュの高さから決まるため、RTK-GNSS の高度とは数 m ずれることがあります (2D の自律走行には影響しません)。
      写真から作ったメッシュなので、木や細い物は形が崩れていたり、地面や壁が波打っていることがあります。
      PCD を自己位置推定 (LiDAR ベースの走行) に使う場合は、実際の LiDAR の点群とは性質が違う点に注意してください。
    - 色は PCL の `PointXYZRGB` と同じ形式 (`rgb` を float32 に詰めたもの) で保存するので、PCL・Open3D・CloudCompare などでそのまま色付きで開けます。
      自己位置推定 (`simple_fastlio_localization`) は `PointXYZI` で読むため、`rgb` は使われず、これまでの x y z だけの PCD と同じように動きます。
      写真の色なので、建物の影になっている所は暗い色になります。
    - ⚠ **Google Maps Platform の利用規約は、コンテンツの取り出し・保存・それをもとにしたデータ (3D モデルなど) の作成を禁じている可能性があります。**
      この機能を使うかどうかは、規約を確認のうえ利用者の責任で判断してください。
  - **地図のパラメータ調整 (PCD / PGM)**:
    - PCD をロードすると「地図のパラメータ調整」パネルが出ます。範囲から作った地図は作ったときの設定が入った状態で、
      それ以外の地図 (LiDAR で作った地図など) は既定値から始まります。
    - 設定を変えて「プレビュー」を押すと、表示中の点群と 2D マップだけを作り直します (ファイルは変わりません)。
      確認してから「PCD・PGM を保存」で保存します。マップ名を変えると別の地図として保存します (原点・初期位置も引き継ぎます)。
      | 対象 | 設定 |
      |---|---|
      | 点群 (PCD) | 点の間隔 (元の点群より粗くするときに間引く)、残す高さ (z の下限・上限)、残す範囲 (地図の上をドラッグで選択) |
      | 2D マップ (PGM) | 解像度、障害物とみなす高さの基準と範囲 (下限・上限)、地面の高さを探す範囲 (地面からの高さのときだけ)、障害物を太らせる幅 |
    - カラー点群は、作り直しても色が残ります。
    - **障害物とみなす高さの基準**は 2 通りから選べます。既定は「PCD の z 座標で指定」です。
      - PCD の z 座標で指定: その地図の PCD の z (原点の地面の高さが z=0) が範囲に入る点を障害物にします (`pcd2pgm` と同じ考え方)。
        パネルに表示中の PCD の z の分布 (最小・5%・中央・95%・最大) を出し、範囲の下限 (水色) と上限 (橙) を点群の広さの半透明の面で表示するので、
        点群と見比べて決められます。坂や段差があると、高い所の地面まで障害物になります。
      - 場所ごとの地面からの高さで指定: 「範囲から地図を作る」と同じ方法です。まわり (地面の高さを探す範囲) の最も低い点を地面とし、そこからの高さで決めます。
      - 範囲から作った直後の PGM は「地面からの高さ」で作られています。パネルを開くと「PCD の z 座標」になっているので、
        同じ数値のままプレビューすると結果が変わることがあります (保存するとその設定が残ります)。
    - 作り直しは、いつも **元の点群** から行います。PCD を初めて書き換えるときに、元の `map/<名前>.pcd` を
      `data/<名前>/source_points.pcd` に残すので、間引いたり切り取ったりした後でも、設定を戻せば元の点群に戻せます。
      設定は `data/<名前>/map_params.json` に保存されます。
    - プレビューした 2D マップはブラシで直してから保存できます (直した分も一緒に保存されます)。
      プレビュー中は解像度や範囲が変わっているため、「2Dマップを保存」ではなく、このパネルの保存ボタンを使ってください。
    - Google 3D Tiles から作った地図は、「Google 3D Tiles から点群を取り直す」で、元より細かい間隔や元の範囲の外まで取り直せます
      (「残す範囲」を選んでいればその範囲、選んでいなければ元の範囲)。原点 (基準点) は変えず、点群の高さを原点の高度にそろえます。
      取り直した点群は保存するまで `data/<名前>/source_points.pending.pcd` に置かれ、保存するとその地図の元の点群になります。
      3D Tiles の読み込み料金がかかり、利用規約の注意は「範囲から地図を作る」と同じです。
    - PCD は x y z だけで書き出します。LiDAR の地図で intensity などの項目があった場合、それらは `source_points.pcd` にだけ残ります
      (点を減らさない設定で別名保存するときは、元のファイルをそのまま複製します)。
  - **ウェイポイントに沿って通行可にする**: 2Dマップ (PGM) 編集の「ウェイポイント移動に追従して通行可にする」がオンなら、
    ウェイポイントを置いた時点 (末尾・先頭・選択中の後・フリーハンド) で、そのまわりと前後の区間を通行可にします。動かすと塗り直します。
    チェックを入れた時点で、既に置いてあるすべてのウェイポイントのまわりと区間も通行可にします。
    チェック中に「マージン」を変えると、新しい幅で塗り直します (狭めたときは、広げた分を元に戻します)。
  - **地図なしでウェイポイントを編集**:
    - PCD・PGM をロードしなくても、ウェイポイントの追加 (末尾・先頭・選択中の後・フリーハンド)・移動・向きの変更・削除・保存ができます。
      地図が無いときは、地面 (z=0) の平面の上に置きます。Google 背景 (現在地・検索した場所・手入力の原点) の上に置くこともできます。
    - 「保存するウェイポイント名」に入れた名前で `waypoints/<名前>.json` に保存します。ウェイポイントのファイルを読み込んだときはその名前、
      地図だけを読み込んだときはマップ名が入ります。既にある別のファイル名で保存するときは上書きを確認します。
    - 地図をロードしていないときに保存すると、いまの Google 背景の原点で緯度・経度・高度を付けます
      (x, y はその原点からの座標です。自律走行に使うときは、同じ原点の地図に合わせてください)。
    - ウェイポイントだけを表示している状態で、あとから PCD・PGM をロードしても、そのまま編集を続けられます
      (保存先は「保存するウェイポイント名」のまま)。
  - **ウェイポイントをまとめて削除・追加**:
    - 「範囲を囲んでまとめて削除」を押して画面上をドラッグで囲むと、囲んだウェイポイントを白く大きく表示して、確認のうえ削除します。
      画面に見えている位置で判定するので、斜めから見ていても囲んだとおりに選べます。
    - 「フリーハンドで線を引いて追加」を押して地図の上をドラッグすると、引いた線に沿って「線を引いて並べる間隔」ごとにウェイポイントを追加します。
      「線を引いて追加する位置」で、末尾・先頭・選択中の後 (選んだウェイポイントの直後。複数選択中は最も後ろの番号の直後) を選べます。
      線を引いた順に並び、向きは線の進む方向です (最後の点は、後ろにウェイポイントがあればそちらを向き、無ければ 1 つ前と同じ向き)。
      属性は「末尾に追加」と同じ既定値です。「ウェイポイント移動に追従して通行可にする」がオンなら、追加した区間も 2D マップで通行可にします。
    - **複数選択してまとめて動かす**: Shift (か Ctrl) を押しながらウェイポイントをクリックすると、選択に足したり外したりできます
      (白く大きく表示)。「範囲を囲んで選択」で囲んだものもまとめて選べます。選んだどれかをドラッグすると、全部が同じだけ動きます。
      「選択中をまとめて削除」で削除、「選択を解除」か Esc で解除します。Shift を押さずにクリックすると、ふつうの 1 つだけの選択に戻ります。
    - どちらも、もう一度ボタンを押すか Esc で解除できます。変更は「ウェイポイントを保存」で書き込みます。
  - **ウェイポイントの到着判定・停止秒数の表示**:
    - Waypoint Editing の「到着判定の範囲 (距離・角度・通過線) を表示」「番号・到着の閾値・停止秒数のラベルを表示」で、
      各ウェイポイントに `waypoint_manager` の判定と同じ意味の表示を重ねます (既定でオン。属性を編集するとすぐ反映されます)。
      | 表示 | 意味 |
      |---|---|
      | 円 (種別の色) | 到着と判定する距離 `xy_tolerance` [m] |
      | 黄色の扇形 | 到着と判定する向きの範囲 (ウェイポイントの向き ± `yaw_tolerance` [rad])。±180° 以上は向きを問わないので描かない |
      | 白い破線 | 前のウェイポイントから来た向きに垂直な線。ロボットがこれを越えると、到着前でも通過扱いになる |
      | 赤い柱 | `stop` の停止秒数 (`value`)。高さ 0.2 m/秒 (上限 12 m) で、柱の上に「停止 N 秒」と表示 |
      | ラベル | 番号、`slow` の減速速度、到着の閾値 (距離 / 角度)、ウェイポイントの向き |
    - 到着は「距離が円の中」かつ「向きが扇形の中」の両方を満たしたときです。属性に閾値が無いウェイポイントは、
      `waypoint_manager` と同じ既定値 (距離 1.0 m、角度 3.14 rad) で表示します。
  - **ウェイポイントの緯度経度高度**:
    - マップの原点 (`init_lat_lon_alt.txt`) が読み込まれている状態でウェイポイントを保存すると、各ウェイポイントの 4 要素目に
      緯度・経度・高度を付けます。高度は、点群 (無ければ 3D Tiles) の地面の高さから求めます。
      ```json
      [[x, y, z], [qx, qy, qz, qw], {"type": "normal", "value": 0, "xy_tolerance": 1.0, "yaw_tolerance": 3.14},
       {"latitude": 35.7107188, "longitude": 139.8126934, "altitude": 38.52}]
      ```
    - `waypoint_manager` と `pcd2pgm_converter.py` は 3 要素目までしか読まないので、これまでどおり自律走行に使えます。
    - 緯度経度高度は保存のたびに位置から計算し直します (Map Viewer の属性の編集欄には出ません。選択中のウェイポイントの情報に表示されます)。
      デバイスの現在地など、そのマップ以外の原点を使っているときは付けません。
    - 使うには API キーが必要です（[セットアップ方法](#3-google-maps-の-api-キー-map-viewer-の-google-背景を使う場合) を参照）。
      インターネットに接続できないと表示できません。

## セットアップ方法

### 1. Python依存パッケージのインストール
必要なPythonパッケージをインストールします。

```bash
pip3 install flask flask-sockets gevent gevent-websocket websockets pyyaml
```

### 2. ファイアウォールの設定

GUIはデフォルトでポート`5050`を使用します。ファイアウォールが有効な場合は、このポートへのアクセスを許可してください。rosbag の取得に vizanti を用いる場合は以下を参考にポートへのアクセスを許可してください

```bash
sudo ufw allow 5050/tcp
sudo ufw allow 5050
sudo ufw allow 5050/tcp
sudo ufw allow 5000
sudo ufw allow 5000/tcp
sudo ufw allow 5001
sudo ufw allow 5001/tcp
sudo ufw allow 8000
sudo ufw allow 8000/tcp
sudo ufw allow 9000
sudo ufw allow 9000/tcp
sudo ufw allow 9090
sudo ufw allow 9090/tcp
sudo ufw enable
```

### 3. Google Maps の API キー (Map Viewer の Google 背景を使う場合)

Map Viewer に Google の衛星写真・3D を重ねる場合だけ必要です。設定しなくても、それ以外の機能はそのまま使えます。

1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを作り、課金を有効にします。
2. 「API とサービス」で **Map Tiles API** を有効にし、API キーを作成します。
3. キーには必ず制限を掛けてください。キーはブラウザに渡るため、GUI を開ける人なら誰でも見られます。
   - API の制限: Map Tiles API のみ
   - アプリケーションの制限: GUI を開くアドレス (例: `http://192.168.0.10:5050/*`) の HTTP リファラ
4. 「場所を検索」で住所や地名を探す場合は、**Geocoding API** と **Places API (New)** も有効にします。
   検索は GUI サーバーから Google に問い合わせるので、3 で HTTP リファラの制限を掛けたキーは使えません。
   その場合は、サーバー用に別のキー (API の制限: Geocoding API と Places API (New)、アプリケーションの制限: サーバーの IP アドレス) を作り、
   環境変数 `GOOGLE_MAPS_SERVER_API_KEY` か `hokuyo_navigation2_gui/google_maps_server_api_key.txt` に設定してください
   (無ければ 5 のキーを使います)。緯度経度や Google マップの URL で探すときは、これらの API は使いません。
5. 次のどちらかでサーバーにキーを渡します。
   - 環境変数 `GOOGLE_MAPS_API_KEY` を設定してから `python3 server.py` を起動する
   - `hokuyo_navigation2_gui/google_maps_api_key.txt` にキーを1行で書く（`.gitignore` 済み。コミットしないこと）。
     ファイルの場合はサーバーの再起動は不要で、Map Viewer を開き直すと反映されます。

利用量に応じて課金されます (2D は表示範囲のタイル枚数、3D は表示のたびのルートタイルセット要求とタイル数、場所の検索は 1 回あたり 1〜2 リクエスト)。
マップを指定せずに Map Viewer を開くと、デバイスの現在地で 2D 衛星写真を自動で表示するため、そのぶんのタイルが読み込まれます。
2D 衛星写真はカメラを動かすたびに見えている範囲のタイルを読み込むので、広く動き回るほど読み込み枚数が増えます。
Map Tiles API の利用規約とポリシー (データのキャッシュ禁止、Google の表記・出典の表示など) に従って使ってください。

### 4. HTTPS で起動する (デバイスの現在地を使う場合)

ブラウザの位置情報は、HTTPS か localhost のページでしか使えません。タブレットなど別の端末から
Map Viewer の「デバイスの現在地」を使う場合は、証明書を用意して HTTPS で起動します
(指定しなければ従来どおり HTTP で起動します)。

```bash
# 自己署名証明書を作る (IP はサーバーを動かす PC のアドレス)
openssl req -x509 -newkey rsa:2048 -nodes -days 3650 \
    -keyout ~/hokuyo_gui_key.pem -out ~/hokuyo_gui_cert.pem \
    -subj "/CN=192.168.0.10" -addext "subjectAltName=IP:192.168.0.10"

# HTTPS で起動
HOKUYO_GUI_SSL_CERT=~/hokuyo_gui_cert.pem HOKUYO_GUI_SSL_KEY=~/hokuyo_gui_key.pem python3 server.py
```

ブラウザで `https://<サーバーのIPアドレス>:5050` を開きます。自己署名証明書のため警告が出るので、内容を確認して進んでください。
Google Maps の API キーにリファラ制限を掛けている場合は、`https://` のアドレスも許可に追加してください。

## 実行方法

### 1. ROS 2環境のセットアップ

[hokuyo_navigation2](https://github.com/hokuyo-rd/hokuyo_navigation2.git) ワークスペースをROS 2環境にセットアップします。

### 2. サーバーの起動

`hokuyo_navigation2_gui`ディレクトリ内で、Flaskサーバーを起動します。

```bash
# サーバーを起動
python3 server.py
```

サーバーが起動すると、コンソールに以下のようなメッセージが表示されます。

```
Flask Server starting at http://0.0.0.0:5050
WebSocket Proxy server started at ws://0.0.0.0:5050/ws
```

### 3. GUIへのアクセス

Webブラウザを開き、サーバーを実行しているマシンのIPアドレスとポート`5050`を指定してアクセスします。

**URL**: `http://<サーバーのIPアドレス>:5050`

## 各機能の使い方

### データ取得
1. メイン画面で「データ取得」ボタンをクリックします。
2. センサやモータドライバの起動スクリプトが実行され、起動画面が表示されます。 
- 起動したいセンサやモータドライバの実行スクリプトは、`hokuyo_navigation2/script/start_getting_rosbag.sh` 内に記述してください。
- このモードのときに、ROS Bag を取得してください。
- 一例として ROS Bag の取得には、[vizanti](https://github.com/hokuyo-rd/vizanti.git) を用いています。

### マッピング
1. メイン画面で「マッピング」ボタンをクリックします。
2. ポップアップから実行したいマッピングの種類（`p2o`, `lio_raw`, `pcd2pgm`）を選択します。
3. ファイルブラウザが表示されるので、処理対象のROS BagまたはPCDファイルを選択します。
4. 「ROS Bag の内容」で、必要なトピックが記録されているかを確認します。
5. 出力ファイル名とパラメータ設定ファイルを選びます。設定ファイルを選ぶと「設定チェック」が
   実行され、コンフィグと ROS Bag の食い違いがあれば、その場で対処方法とともに表示されます。
   問題があるまま実行しようとすると確認ダイアログが表示されます。
6. 食い違いがあれば「パラメータ設定ファイルを編集する」を開き、プルダウンから
   ROS Bag に記録されているトピック名・座標系を選び直して保存します。
   元のファイルを残したい場合は、保存するファイル名を変えてください。
7. 処理を開始すると、進捗と「実行ログ」が表示されます。失敗した場合は、原因の説明が
   実行ログの上に表示されます。うまくいかないときは「ログをコピー」で実行ログを控えて
   担当者に連絡してください。

> 実行ログは `hokuyo_navigation2/log/gui/` に保存されます（最新50件のみ保持）。

### ナビゲーション
1. メイン画面で「自律走行」ボタンをクリックします。
2. **単一マップ**: 「Map File」と「Waypoint File」をドロップダウンから選択し、「実行」ボタンを押します。
3. **マルチマップ**: 「CSV File」からシナリオファイルを選択し、「実行」ボタンを押します。

### ファイル管理と編集
1. メイン画面で「File Management」ボタンをクリックします。
2. 管理したいファイルの種類（Map, Waypoint, Config）を選択します。
3. ファイルブラウザが表示されます。
   - **新規CSVファイル作成**: 「作成する形式」で、マッピング用パラメータ設定と
     マルチマップ走行シナリオのどちらを作るか選べます。マッピング用を選ぶと
     「参考にするROS Bag」も選べるようになり、そのROS Bagに記録されている
     トピック名と座標系をあらかじめ埋めた状態でファイルが作られます。
     作成後はそのままプルダウン編集画面が開き、参考にしたROS Bagも引き継がれます。
   - **マッピング設定を編集**: マッピング用のパラメータ設定CSVには「マッピング設定を編集」
     ボタンが出ます。項目ごとのプルダウンで編集でき、「トピック名・座標系の候補にする
     ROS Bag」を選ぶと、そのROS Bagに記録されているトピック名・座標系が候補になります
     （緑=型や座標系が一致、赤=そのROS Bagに存在しない値）。
   - **テキスト編集**: 各ファイルの横にある「テキスト編集」ボタンで、プレーンテキストとして編集できます。
   - **CSV編集**: `.csv`ファイルの横にある「編集」ボタンで、専用のテーブルエディタが開きます。
   - **Map Viewer**: メイン画面の「Map Viewer」ボタンから、マップとウェイポイントを3Dで表示・編集できます。
   - **削除**: 各ファイル/フォルダの横にある「削除」ボタン、またはチェックボックスで複数選択して一括削除が可能です。
   - **名前変更**: ファイル名をダブルクリックすると、名前を変更できます。
